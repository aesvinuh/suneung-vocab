# 수능 단어: 뉘앙스 암기 웹앱

대중교통에서 폰 하나로, 한 손으로 계속 푸는 수능 영단어 앱입니다.
철자가 아니라 **단어를 보면 뜻과 뉘앙스가 바로 떠오르게** 만드는 것이 목표입니다.

- Vite + React, 서버·로그인 없음. 데이터는 브라우저 IndexedDB에 저장됩니다.
- 외부 API를 쓰지 않습니다. 처음 페이지를 열 때만 인터넷이 필요합니다.
- 처음 열면 홈에서 **샘플 단어 15개 넣기**를 눌러 바로 시작할 수 있습니다.

## 2. 데이터 구조

IndexedDB `suneung-vocab`에 저장소(object store)가 2개 있습니다.

**words**: 단어 1개당 1레코드

```js
{
  id: 'uuid',
  word: 'reluctant',
  meanings: ['꺼리는', '마지못해 하는'],   // 필수, 여러 개
  pos: 'adj',                              // n v adj adv prep conj phr
  tone: 'negative',                        // positive | negative | neutral | '' (뉘앙스 문제용)
  nuance: '약한 부정. 하기 싫어서 꺼림…',   // 자유 메모
  related: 'reluctant to do: ~하기를 꺼리다', // 관련 표현·숙어
  form: 'reluctantly',                     // 본문 형태 (지문에 나온 형태)
  memo: '…',                               // 기타 메모 (강세 등, 문제에 안 씀)
  profile: {                               // 뉘앙스 프로필 — 뉘앙스 문제는 확정된 것만 사용
    direction: 'negative',                 //   평가 방향: positive | negative | neutral | context(문맥 의존)
    role: 'evaluative', signal: '',        //   글 속 역할: signal(흐름 신호어: contrast|cause|concession|emphasis) | evaluative | content
    intensity: 'medium',                   //   강도: weak | medium | strong
    keywords: ['소극적'], diff: '…',        //   느낌 키워드 1~3개, 유사어와의 차이
    confirmed: true, confirmedAt,          //   확정 여부
    suggested: { … },                      //   AI 초안 (확정 전)
  },
  illusion: { count, lastAt },             // 착각 단어 ('뉘앙스까지 떠오름' 후 뉘앙스 문제 오답)
  ai: {                                    // AI가 미리 만든 문제 재료 (학습 중엔 이것만 사용)
    examples: [{ id, en, ko, why, uses, lastUsedAt }],      // 수능 지문 스타일 예문 풀
    userExample: { why, uses, lastUsedAt },                // 내 예문(example)의 이유·사용 기록 (내 예문은 지우지 않음)
    confusables: [{ word, pos, meanings, forms, type, why, transitivity, pattern, level }], // 헷갈리는 단어 5~8개
    grammar: { transitivity, pattern, level, forms },      // 타동사/자동사, 뒤 구조, 난이도, 활용형
    generatedAt, examplesAt, lastAttemptAt,
  },
  definition: 'not willing to do …',        // 영영 뜻풀이 (자동 채우기)
  example: 'Many residents were reluctant to …',
  exampleKo: '많은 주민들이 … 꺼렸다.',
  synonyms: ['hesitant'], antonyms: ['willing'],
  sources: { meanings: 'ai', example: 'mw' }, // 칸별 출처 (mw | fd | ai | user)
  createdAt, updatedAt,                    // 자동
  stats: {                                 // 자동
    shown, correct, wrong,                 // 출제·정답·오답 횟수
    lastShownAt, lastWrongAt,              // 마지막 출제·오답 시각
  },
  note: {                                  // 오답 노트 (자동)
    inNote,            // 현재 노트에 있는지
    streak,            // 노트 학습 연속 정답
    enteredAt, graduatedAt, graduations,
    confusedWith: { [단어id]: 횟수 },      // 틀릴 때 골랐던 오답 보기
  },
}
```

**daily**: 날짜별 풀이 수 `{ date: '2026-10-22', answered, correct }` (홈의 '오늘 푼 문제/정답률')

'느낌 메모'는 예전 '뉘앙스 메모'(nuance) 칸을 그대로 쓴 자유 메모입니다. 단어장 구분 없이 하나의 목록입니다. `tone`을 비워 두면 뉘앙스 메모에 '긍정/부정/중립' 중 한 단어만 들어 있을 때 자동으로 인식합니다.

## 3. 출제 가중치 (`src/lib/weights.js`)

매 문제마다 후보 단어 각각의 가중치를 계산하고, 가중치에 비례하는 확률로 하나를 뽑습니다.

```
가중치 = max(최소값 0.5,  최근추가 + 오답률 + 경과시간 [+ 오답노트 보너스])
```

| 항목 | 계산 | 기본값 의미 |
|---|---|---|
| 최근 추가 | `6 × 0.5^((추가 후 일수 − 2) / 3)` | 추가 후 2일은 +6 그대로, 이후 3일마다 절반 (5일 뒤 +3, 8일 뒤 +1.5 …) |
| 오답률 | `6 × (오답 + 1) / (출제 + 3)` | 새 단어는 +2로 시작. 7/10 틀린 단어 ≈ +3.7, 0/30 ≈ +0.2 |
| 경과 시간 | `3 × min(1, 마지막 출제 후 일수 / 10)` | 10일 이상 안 나왔거나 처음이면 +3 |
| 착각 단어 | `5 × min(착각 횟수, 3) × 0.5^(마지막 착각 뒤 일수 / 14)` | 크게 올림. 14일마다 절반 |
| 다시 넣음 | `1.5 × min(다시 넣은 횟수, 3) × 0.5^(마지막으로 다시 넣은 뒤 일수 / 7)` | 이미 있는 단어를 또 넣으면 조금 더 자주. 7일마다 절반 |
| 오답 노트 보너스 | `1.5 × min(틀린 횟수, 8)` | 오답 노트 학습에서만 |
| 쿨다운 | 최근 5문제 안에 나온 단어는 제외 | 단어가 6개 미만이면 자동으로 줄어듦 |
| 최소값 | 0.5 | 잘 아는 단어도 가끔 나옴 |

예: 오늘 추가한 새 단어 ≈ 11, 자주 틀리고 오래된 단어 ≈ 4~7, 30번 다 맞힌 단어 ≈ 0.5~3.

출제가 마음에 들지 않으면 `WEIGHT_CONFIG` 숫자만 바꾸면 됩니다. 단어 수정 화면 아래에 그 단어의 현재 가중치 내역이 표시됩니다.
같은 파일에 `TYPE_WEIGHTS`(문제 유형별 출제 비율)와 `GRADUATION`(졸업 조건)도 있습니다.

## 4. 문제 유형

단어를 먼저 뽑은 뒤, 그 단어로 만들 수 있는 유형 중 하나를 랜덤으로 고릅니다.

| 유형 | 필요한 데이터 |
|---|---|
| 1. 단어 → 뜻 4지선다 | 뜻, 다른 단어 3개 이상 |
| 2. 예문 빈칸 → 단어 4지선다 | 예문에 단어(활용형 포함)가 있어야 함 |
| 3. 예문 밑줄 → 문맥상 의미 | 예문 |
| 4. 유의어 중 문맥에 맞는 단어 | 예문 + 서로 유의어로 등록된 다른 단어 (예문 해석을 힌트로 표시) |
| 5. 뉘앙스 (4종 랜덤) | **확정된 뉘앙스 프로필**. ① 예문 속 단어로 본 필자의 태도(평가 방향 + 글 속 역할) ② 글 속 역할(흐름 신호어·평가어·내용어) ③ 느낌이 가장 가까운 단어(키워드·강도) ④ 유사어 두 개 중 문맥에 더 자연스러운 것(유사어와의 차이) |
| 6. 자기평가 카드 | 항상 가능 |

- 오답 선지 규칙은 전부 `src/lib/distractors.js`에 있습니다 (`DISTRACTOR_RULES`):
  - 품사 일치 필수, 빈칸 문제는 오답도 정답과 같은 활용형(-s/-ed/-ing…)으로 변형, 뜻 문제는 한국어 뜻도 같은 형태(동사 "~다", 형용사 "~한/~적인")
  - 정답과 같은 뜻·유의어는 제외, 정답이 수능 수준(난이도 3 이상)이면 기초 단어(1) 제외
  - 우선순위: 내 단어장 단어 → AI 헷갈리는 단어 풀. 그 안에서 타동사/자동사·뒤 구조·난이도·뜻 범위가 비슷한 단어 우선
  - 조건에 맞는 오답이 3개 미만이면 그 유형은 내지 않고 다른 유형으로 대체
- 빈칸 문제에서는 정답과 유의어 관계인 단어나 뜻이 같은 단어를 오답 보기에서 뺍니다(정답이 두 개가 되지 않도록).
- 불규칙 활용(went, fought)은 예문에서 `*fought*`처럼 별표로 감싸면 그 부분을 빈칸으로 씁니다.
- 뉘앙스 고르기(메모형) 보기 규칙: 각 단어의 뉘앙스 메모 **전체를 한 덩어리로** 쓰고 줄 단위로 쪼개지 않습니다. 정답 단어(활용형 포함)를 ○○로 가린 뒤 남는 글자가 10자 미만인 메모, 본문 형태·반의어·숙어가 섞인 메모는 보기로 쓰지 않습니다. 같은 문구의 보기는 하나만 쓰고, 조건에 맞는 오답 보기가 3개 미만이면 이 유형 대신 다른 유형을 냅니다.
- 뉘앙스 칸에는 뉘앙스만 쓰고, 숙어는 '관련 표현', 지문에 나온 형태는 '본문 형태', 강세 등은 '기타 메모' 칸에 씁니다. 예전 버전에서 뉘앙스 칸에 섞여 들어간 정보는 **설정 → 데이터 정리**(먼저 JSON 백업 안내)로 옮길 수 있습니다.
- 자기평가 → 후속 문제: '모름'은 학습 카드(뜻·뉘앙스 프로필·예문)를 보여 주고 5~10문제 뒤 같은 단어를 다시 냅니다(오답으로 기록). '뜻만 떠오름'은 바로 뜻 확인 문제, '뉘앙스까지 떠오름'은 바로 뉘앙스 문제(확정 프로필이 없으면 뜻 문제)로 검증합니다. 뉘앙스까지 떠오른다고 했는데 틀리면 **착각 단어**로 기록하고 가중치를 크게 올립니다(오답 노트 '착각' 탭).
- 정답이어도 해설을 보여 주고 '다음'으로 넘어갑니다. 해설에는 모든 선지의 뜻(내 단어는 저장된 뜻·느낌, AI 단어는 생성 때 저장한 뜻·'왜 헷갈리는지'), 정답 이유, 고른 오답이 안 맞는 이유가 나오고, AI 헷갈리는 단어 옆에는 '단어장에 추가' 버튼이 있습니다. 모든 해설 화면의 **'내 느낌은 달라'**로 그 단어 프로필을 바로 고칠 수 있습니다.

## 5. 오답 노트

- 한 번이라도 틀리면 자동 등록됩니다. 틀릴 때 고른 보기 단어가 '헷갈렸던 단어'로 쌓입니다.
- **오답 노트 학습**에서 연속 3번 맞히면 졸업합니다. 기록은 남고, 다시 틀리면 재등록됩니다.
  (일반 학습에서 맞힌 것도 세려면 `GRADUATION.countInNormalMode = true`)
- 목록은 틀린 횟수 / 오답률 / 최근에 틀린 순으로 정렬할 수 있고, 졸업한 단어는 '졸업' 탭에 있습니다.

## 6. 단어 입력

- **단어 추가**: 단어와 뜻만 쓰고 바로 '추가하고 계속'. 나머지는 '+ 품사 · 뉘앙스 · 예문 · 유의어'를 펼쳐서 입력합니다.
- **일괄 추가**: 정리한 메모를 그대로 붙여 넣으면 단어별로 칸을 나누고, **단어마다 칸이 표시된 미리보기**를 보여 준 뒤 추가합니다. 이미 있는 단어는 건너뜁니다.

  여러 줄 형식 (단어 줄로 시작, 빈 줄은 있어도 없어도 됨):
  ```
  reluctant (형)
  꺼리는, 마지못해 하는
  뉘앙스: 부정적. 하기 싫어서 꺼림
  He was reluctant to admit his mistake.
  그는 자기 실수를 인정하기를 꺼렸다.
  유의어: hesitant, unwilling
  ```
  - 머리말(`뜻:` `뉘앙스:` `예문:` `해석:` `품사:` `유의어:` `반의어:`)이 있으면 그대로 따릅니다.
  - 없으면 내용으로 판단: 영어 1~3단어 줄 = 새 단어, 영어 문장 = 예문, 예문 바로 다음 한국어 = 해석, 첫 한국어 줄 = 뜻, 그 밖의 한국어 = 뉘앙스.
  - 품사는 `reluctant (형)`, `[동] 줄이다`, `adj.`처럼 써도 됩니다. `1.` `-` `•` 같은 번호·글머리표는 무시합니다.
  - 한 줄 형식도 됩니다: `vivid - 생생한` 또는 `단어 | 뜻 | 뉘앙스 | 예문 | 예문 해석 [| 품사 | 유의어 | 반의어]` (엑셀 표 복사도 가능)
  - 단어만 죽 나열하면 뜻 없는 '미완성' 단어로 들어갑니다.
  - **이미 있는 단어를 다시 넣으면** 건너뛰지 않고, 비어 있던 칸만 채운 뒤 '다시 넣은 횟수'를 올려 더 자주 출제합니다(단어 추가 화면도 같음).
  - `단어 | 품사 | 뜻` 표 줄 아래에 예문·해석 줄이 이어지는 형식, `(← settlements)` 같은 본문 형태 메모, `(반의: distributive)` 같은 괄호 설명도 알아봅니다.
  - Claude·ChatGPT가 정리해 준 글(마크다운 제목·굵은 글씨·목록·표, `→ 예문 (해석)`, `Meaning:`/`Example:` 같은 영어 머리말)도 그대로 붙여 넣으면 됩니다. 표는 첫 줄의 칸 이름 순서를 따릅니다.
  - 화면의 **AI에게 보낼 요청문 복사** 버튼으로 이 앱이 확실히 알아보는 형식을 요청하는 문장을 복사할 수 있습니다.
  - 규칙은 `src/lib/parse.js`, 예시는 `tests/parse.test.js`에 있습니다.

## 7. 단어 자동 채우기

단어 추가 화면에서 영어 단어만 쓰고 **자동 채우기**를 누르면:

1. **여러 사전을 동시에 조회**합니다.
   | 사전 | 가져오는 것 | 키 |
   |---|---|---|
   | Merriam-Webster Learner's | 품사·뜻풀이·예문·유의어 (학습자용 편집 사전, 가장 우선) | 무료 키 필요 |
   | Wiktionary 영어판 | 품사·뜻풀이·예문 (수록 단어가 많음) | 불필요 |
   | Free Dictionary | 뜻풀이·예문·유의어·반의어 (가끔 장애 → 있으면 사용) | 불필요 |
   | Datamuse | 유의어·반의어 (WordNet 기반) | 불필요 |
2. **AI가 모든 뜻풀이를 종합**해 같은 뜻끼리 합치고, 고어·전문용어는 빼고, 수능에 자주 나오는 순서로 **한국어 뜻 목록**을 만듭니다. 각 뜻에 근거 사전이 표시됩니다. 외울 뜻을 고릅니다(여러 개 가능).
3. AI가 고른 뜻과 근거 자료로 **뉘앙스 메모·감정 톤·예문 해석**을 쓰고, 모아 둔 유의어/반의어 후보 중 그 뜻에 맞는 흔한 단어만 고릅니다.
4. 바로 저장하지 않고 **미리보기**에 보여 줍니다. 칸마다 출처가 붙고, 고친 칸은 '직접 입력'으로 바뀝니다.

AI가 지어내지 못하게 막는 장치:
- 영영 뜻풀이 칸은 사전 원문 그대로(공신력 순: MW → Wiktionary → Free Dictionary).
- 예문은 사전에 실린 문장만 인정합니다. AI가 고른 예문이 사전에 없으면 버립니다(사전 예문이 하나도 없을 때만 AI가 새로 쓰고 'AI 종합'으로 표시).
- 근거 번호가 없는 뜻, 후보에 없는 유의어/반의어는 버립니다.

- Claude 키가 없으면 대표 사전(MW → Wiktionary → Free Dictionary 순)의 영어 뜻풀이로 고르고, 사전 내용만 채웁니다.
- 단어 칸 아래 **네이버 영어사전에서 보기 ↗** 링크로 네이버 사전 페이지를 새 탭으로 열어 대조할 수 있습니다.
  네이버는 공개 사전 API가 없어(내부 주소는 브라우저 호출이 막혀 있고 약관상 자동 수집도 허용되지 않음) 링크로만 연결합니다.
- 한국어 뜻을 위키낱말사전(영한)에서 가져오던 방식은 오타·어색한 뜻·빠진 단어가 많아 없앴습니다.
- Claude 요청은 단어마다 2번(뜻 종합 + 해설)입니다.
- 인터넷이 끊기면 버튼이 '오프라인'으로 바뀌고 직접 입력만 됩니다.
- **미완성 단어 일괄 자동 채우기**: 뜻 없이 단어만 추가해 두면 '미완성'이 됩니다(뜻·뉘앙스·예문 중 하나라도 비면 미완성).
  단어 목록이나 홈의 링크 → 한 번에 최대 20개 → 뜻 고르기 → 미리보기에서 확인 후 저장. **비어 있는 칸만 채우고 직접 쓴 내용은 덮어쓰지 않습니다.**
- 뜻이 없는 단어는 출제되지 않습니다.
- 사용한 Claude 요청은 Anthropic 콘솔 계정에 사용량만큼 청구됩니다. Merriam-Webster는 비상업용 무료(하루 1,000회)입니다.
- 관련 코드: `src/lib/dictionary.js`(사전), `src/lib/aiFill.js`(Claude), `src/lib/autofill.js`(흐름·병합 규칙).

### API 키 관리

- 설정 → **자동 채우기 API 키**에 입력합니다. 키는 **그 기기 그 브라우저의 localStorage에만** 저장됩니다.
- 코드에 키를 넣지 않으므로 GitHub에 올라갈 일이 없고, JSON 백업 파일에도 포함되지 않습니다. 폰·컴퓨터(아이폰은 홈 화면 앱도)에서 각각 입력하세요.
- '확인' 버튼으로 키가 맞는지 확인할 수 있습니다(Claude 키 확인은 요금이 들지 않는 모델 정보 조회).
- 이 페이지를 열 수 있는 다른 사람이 키를 볼 수는 없지만, **본인 폰에 저장된 키는 그 폰을 쓰는 사람이 볼 수 있습니다.** 공용 기기에는 넣지 마세요.

### 왜 중계 서버(Vercel) 없이 되나요?

브라우저는 다른 사이트의 API를 부를 때, 그 API가 응답에 "이 사이트에서 불러도 된다"는 허가(CORS 헤더)를 주는지 확인합니다. 2026-10-24에 직접 확인한 결과:

| API | CORS | 결과 |
|---|---|---|
| Merriam-Webster (`dictionaryapi.com`) | `Access-Control-Allow-Origin: *` | 브라우저에서 바로 호출 가능 |
| Free Dictionary (`dictionaryapi.dev`) | `*` 허용 (장애가 잦음) | 바로 호출. 장애 시 나머지 사전만 사용 |
| Wiktionary 영어판 (`en.wiktionary.org/api/rest_v1`) | `*` 허용 | 바로 호출 |
| Datamuse (`api.datamuse.com`) | 요청한 사이트 허용 | 바로 호출 |
| 네이버 영어사전 | 공개 API 없음, CORS 허용 안 함 | 자동 조회 불가 → 사전 페이지 링크만 제공 |
| Claude (`api.anthropic.com`) | `anthropic-dangerous-direct-browser-access` 헤더를 보내면 허용 | 바로 호출 (SDK `dangerouslyAllowBrowser`) |

그래서 Vercel 서버리스 함수는 필요 없습니다. Anthropic이 브라우저 직접 호출에 "dangerous"라는 이름을 붙인 이유는, 키를 웹페이지 코드에 박아 두면 누구나 훔쳐 갈 수 있기 때문입니다.
이 앱은 키를 코드에 넣지 않고 **본인이 본인 기기에 입력**하는 방식이라 그 위험이 없습니다.
나중에 다른 사람도 쓰게 하면서 내 키를 숨겨야 한다면, 그때는 Vercel 같은 서버에 키를 두고 중계해야 합니다.

## 7-1. AI 문제 재료 풀과 사용량

Claude API 키가 있으면 단어마다 아래를 **미리** 만들어 IndexedDB에 저장합니다(`src/lib/pools.js`). 문제를 풀 때는 API를 부르지 않으므로 지하철·오프라인에서도 그대로 됩니다.

- 예문 풀: 수능 지문 스타일 예문 5개 + 해석 + '이 문장에서 왜 이 단어인지'. 출제 때 내 예문과 함께 순환(가장 적게 쓴 것 우선, 방금 쓴 것 피함), 모든 예문을 3번씩 쓰면 새 예문을 만들 대상이 됩니다. 내가 입력한 예문은 풀에 포함되고 지워지지 않습니다.
- 헷갈리는 단어 5~8개: 정답과 같은 품사, 유형(철자 혼동/의미 혼동/같은 의미 범위), 뜻, 활용형, '왜 헷갈리는지'. 내 단어장에 있는 단어는 뺍니다.
- 문법 정보(타동사/자동사, 뒤 구조, 난이도, 활용형)와 뉘앙스 프로필 초안.
- 만드는 시점: 단어 추가 직후, 앱을 열 때(인터넷 연결 시) 부족한 것만 백그라운드로. 설정의 '지금 전체 풀 채우기'로 바로 만들 수도 있습니다. 백그라운드에서는 한 번 시도한 단어를 하루 동안 다시 요청하지 않습니다.
- 토큰 관리: 요청 한 번에 단어 5개씩 묶음, 하루 최대 요청 수(기본 20회)를 설정에서 지정, 이번 달 사용량(요청 수·토큰·대략 금액)을 설정에 표시(`src/lib/usage.js`).
- 키가 없으면 AI 재료 없이 내 단어장만으로 출제합니다.

## 7-2. 뉘앙스 프로필 확인

- 단어 추가(자동 채우기)·풀 생성 때 AI가 사전 정보를 근거로 프로필 초안을 만들고, 사용자가 '확정'(또는 고친 뒤 확정)합니다.
- 홈에 미확정 개수가 나오고, '한 번에 확인하기'(#/profiles)에서 몰아서 확정할 수 있습니다. 단어 수정 화면에서도 고칠 수 있습니다.

## 8. 폰·컴퓨터 동기화 (GitHub Gist)

단어와 학습 기록을 **내 GitHub 계정의 비밀 Gist**(파일 `suneung-vocab-sync.json`) 하나에 두고 기기끼리 맞춥니다. 서버는 필요 없습니다(GitHub API가 브라우저 호출 허용).

설정 방법 (기기마다 한 번):
1. 설정 → 폰·컴퓨터 동기화 → **GitHub 토큰 만들기 페이지** 링크 (gist 권한이 미리 체크된 화면이 열림)
2. Expiration은 **No expiration** → 맨 아래 **Generate token** → `ghp_…` 토큰 복사
3. 앱의 토큰 칸에 붙여 넣고 **토큰 저장하고 연결**. 다른 기기에도 같은 토큰을 넣습니다(토큰은 한 번만 보이니 카톡 '나와의 채팅' 등으로 옮겨 두기).

동작:
- 앱을 열 때, 앱으로 다시 돌아올 때, 무언가 바꾸고 15초 뒤에 자동으로 동기화합니다. 설정의 **지금 동기화**로 바로 할 수도 있습니다.
- 같은 단어를 두 기기에서 고쳤으면 **더 최근에 바뀐 쪽**(수정 또는 출제 시각 기준)을 씁니다.
- 지운 단어는 지운 기록을 함께 저장해서 다른 기기에서 되살아나지 않습니다. '전체 삭제'도 다른 기기에 반영됩니다.
- 오늘 푼 문제 수는 기기별로 세서 합칩니다.
- 토큰은 그 브라우저에만 저장되고 'gist' 권한만 있어서 코드 저장소는 건드릴 수 없습니다. 비밀 Gist는 목록에 안 보이지만 주소를 아는 사람은 볼 수 있으니 주소를 공유하지 마세요.
- 코드: `src/lib/sync.js`(합치기 규칙·Gist 입출력), 테스트 `tests/sync.test.js`.

## 8-1. 백업

설정 → **JSON으로 내보내기 / 불러오기**. 불러올 때 '합치기'(같은 단어는 건너뜀) 또는 '전체 교체'를 고를 수 있습니다.

[Node.js](https://nodejs.org) LTS(20 이상)를 설치한 뒤:

```bash
cd suneung-vocab
npm install
npm run dev        # http://localhost:5173 (코드 수정이 바로 반영됨)
npm test           # 로직 테스트
npm run build      # dist/ 다시 만들기
```

`npm run dev`의 주소(localhost:5173)는 배포 주소와 저장소가 따로라 단어 데이터가 따로 저장됩니다.

## 11. 무료 배포: GitHub Pages (추천)

이 저장소에는 자동 배포 설정(`.github/workflows/deploy.yml`)이 이미 들어 있습니다.

1. [github.com](https://github.com)에 가입하고 로그인합니다.
2. 오른쪽 위 **+** → **New repository**. 이름(예: `suneung-vocab`)을 정하고 **Public**을 선택한 뒤 **Create repository**를 누릅니다.
   (무료 계정에서 GitHub Pages는 Public 저장소만 지원합니다. 저장소에는 코드만 올라가고, 내 단어 데이터는 폰에만 있으니 공개돼도 괜찮습니다.)
3. 컴퓨터 터미널에서 프로젝트 폴더로 가서 올립니다 (`아이디`를 내 GitHub 아이디로 바꾸세요):
   ```bash
   cd suneung-vocab
   git init
   git add .
   git commit -m "first commit"
   git branch -M main
   git remote add origin https://github.com/아이디/suneung-vocab.git
   git push -u origin main
   ```
   비밀번호를 물으면 GitHub 비밀번호 대신 **Personal access token**을 넣어야 합니다
   (Settings → Developer settings → Personal access tokens). [GitHub Desktop](https://desktop.github.com)을 쓰면 이 과정이 더 쉽습니다.
4. GitHub 저장소 페이지 → **Settings** → 왼쪽 **Pages** → **Build and deployment**의 Source를 **GitHub Actions**로 바꿉니다.
5. 저장소의 **Actions** 탭에서 `Deploy to GitHub Pages`가 초록색 체크가 될 때까지 1~2분 기다립니다.
   (4번보다 push를 먼저 해서 첫 실행이 실패했다면, Actions 탭에서 그 실행을 열고 **Re-run jobs**를 누르세요.)
6. 주소 `https://아이디.github.io/suneung-vocab/`를 폰 크롬에서 엽니다.
7. 크롬 메뉴 **⋮** → **홈 화면에 추가**를 누르면 앱처럼 전체 화면으로 실행됩니다.

이후에는 코드를 고치고 `git push`만 하면 자동으로 다시 배포됩니다. 배포해도 폰에 저장된 단어는 그대로 남습니다.
